# There are 3 ways to do fine tuning :

# But fine tuning has a lot of problems :

# There is one more way to solve it which is In-Context learrning 

# In-Context learning --> is a core capability of LLM's where the models 
# learn to solve a task purely on the basis of the examples given in the prompt without being trained or updating the weights

# Now this is an emergent property means this is a behaviour which suddenly appeared in models affter reaching certain scale and complexity

# Now we can even give the full context in the prompt rather than example and make the llm to answer our question , 
# like we can givve our full diary in the prompt only , this is 
# RAG (Retrieval Augmented Generation)
# RAG is a way of making the language model faster by giving it extra information at the time we ask the question from it 

# There are 4 stages in rag :
# 1) Indexing --> Here we will create or collect the knowledge base which will act as the context to answer our query
# 2) Retrieval --> Now we do not use the full context , we find the part of the context in which the answer to the query can be present and thus we get that part
# 3) Augmentation --> We give the query with the important part to the llm to answer our query
# 4) Generation --> Then llm generates the final answer

############### INDEXING ***************************

#  Indexing is the process of preparing knowledge base so that it can be efficiently used at query time 
# It has 4 steps -->

# 1) Document Ingestion --> Your load your knowledge source into the memory
# eg: pdf reports , word document , youtube transcript , github repos etc.
# We can use document loaders here like : PyPDFLoader , YoutubeLoader etc

# 2) Text chunking --> Break large document into small , semantically meaningful chunks ,
# because for answer a query we cannot give the llm the whole knowledge base , because llm's have a contect window for a conversation
# and the whole external knowledge base might not fit into it 
# ALso Smaller chunks provides better semantic search 
# eg: RecursiveTextSplitters , SemanticChunkers

# 3) Embedding Generation -> Convert each chunk into dense vector(embedding) that captures the meaning 
# Because it helps us to implement semantic search between the query and the chunks , so as to knwo which query can have the answer
# eg of embedding Generators : OpenAIEmbeddings , SemanticTransformerEmbeddings

# 4) Store the embeddings in vector store/database --> store the vectors along with the original chunk text + metadata in a vector database
# This helps in menaging store and better and efficient semantic search and a lot of other database features 
# eg of vector stores : chroma , faiss , pinecone , Qdrant

##################### Retrieval ############################

# Now when a query comes then we have to get the relevant chunks so as to give them to the llm to get the answer , because it is not effieient to give the whole knowledge base

# Retrieval -> is a real time process of finding the most relevant pieces of information from the pre built index based on user question 

################# AUgmentation ##########################

# Now we give the query and the revelant data (combined chunks) to the llm
